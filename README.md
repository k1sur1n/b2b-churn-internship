# Подготовка к стажировке: прогнозирование оттока B2B-клиентов

Учебный репозиторий для подготовки студентов-стажёров к проекту «Модель
прогнозирования оттока (churn) B2B-клиентов телеком-компании». Курс рассчитан
на **4 недели**, идёт параллельно с еженедельными семинарами и асинхронным
ревью в Pull Request'ах.

## Как пользоваться репозиторием

1. **Форкните** этот репозиторий к себе в GitHub.
2. Клонируйте свой форк локально.
3. На каждую лабораторную работу создавайте отдельную ветку: `week1-eda`,
   `week2-dataset`, `week3-baseline`, `week4-experiment`.
4. По готовности недели — открывайте Pull Request **из своей ветки в `main`
   своего форка** и зовите руководителя на ревью (добавьте его в reviewers).
5. После фидбека вносите правки в той же ветке — PR обновится автоматически.
6. Смёрженный `main` после недели 4 — это ваш финальный артефакт для защиты.

## Настройка окружения

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Расписание (кратко)

| Неделя | Тема | Лабораторная | Семинар |
|---|---|---|---|
| 1 | Окружение + EDA | `01_eda.ipynb` | Окна наблюдения/прогноза, гипотеза "одна модель или много" |
| 2 | Сборка выборки | `02_dataset.ipynb` | Data leakage: разбор на примерах |
| 3 | Признаки + baseline | `03_baseline.ipynb`, `04_features.ipynb` | Метрики ранжирования и бизнес-язык |
| 4 | Эксперимент A/B/C + защита | `05_segments_experiment.ipynb`, `06_final_report.ipynb` | Мини-защита проектов |

Подробное расписание с датами — в [`docs/schedule.md`](docs/schedule.md).
Полное ТЗ на каждую неделю — в соответствующих файлах `docs/weekN_*.md`.

## Правила проекта

- Файлы в `data/raw/` — только для чтения.
- Признаки строятся **только** из данных до точки отсчёта (snapshot), таргет —
  только из данных после. Нарушение — утечка данных (data leakage).
- Разбиение train/test — только по времени (out-of-time), никогда случайным
  перемешиванием.
- Ведите `docs/journal_<имя>.md` — журнал по своей работе (что попробовали,
  какая метрика получилась, что решили). Коммитьте в конце каждого рабочего дня.
