# Неделя 1 — Окружение и EDA

## Цель недели

Настроить рабочее окружение и разобраться, что вообще лежит в данных, прежде
чем что-либо моделировать.

## Что сделать

1. Настроить venv, установить зависимости из `requirements.txt`.
2. До семинара — прочитать материалы по темам: отток в B2B как процесс;
   окно наблюдения / окно прогноза; гипотеза "одна модель или много моделей".
3. Загрузить учебный датасет, сохранить в `data/processed/*.parquet`.
4. В `notebooks/01_eda.ipynb` пройти по чек-листу EDA для каждой таблицы:
   - Что является строкой в таблице (клиент? клиент-месяц? услуга?)
   - Какой ключ связывает таблицы, какая доля клиентов "склеивается"
   - За какой период есть данные, есть ли дыры в месяцах
   - Как в данных видно отток (дата расторжения? падение начислений?)
   - Сколько клиентов в каждом сегменте и по каждому продукту
   - Есть ли дубликаты (по ключу и в целом)
   - Есть ли аномалии (отрицательные платежи, нули, выбросы)
5. Посчитать базовую долю оттока в целом и по сегментам/продуктам/регионам.
6. Построить графики динамики revenue для 5-10 ушедших и 5-10 оставшихся
   клиентов — визуально понять, как выглядит отток.
7. Функцию профилирования таблицы оформить в `src/eda.py`, чтобы переиспользовать.
8. Завести `docs/journal_<имя>.md` и вписать туда ответы на 7 вопросов из чек-листа.

## Deliverable (что должно быть в PR)

- [ ] `notebooks/01_eda.ipynb` — воспроизводится по "Restart & Run All"
- [ ] `src/eda.py` — функция `explore(df, name)`
- [ ] `docs/journal_<имя>.md` — ответы на 7 вопросов EDA
- [ ] Графики динамики ушедших/оставшихся клиентов сохранены в ноутбуке

## На что обратит внимание ревьюер

- Правильно ли определён "объект наблюдения" в данных (клиент vs договор vs услуга)
- Не пропущены ли явные аномалии (дубликаты, отрицательные суммы)
- Есть ли осмысленный вывод по разнице оттока между сегментами (не просто цифры)
