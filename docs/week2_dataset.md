# Неделя 2 — Сборка обучающей выборки

> Краткая карточка. **Полная версия — рабочая тетрадь, раздел 6.**

**Даты:** 10.08 – 16.08 · **Ветка:** `week2-dataset` · **Ноутбук:** `02_dataset.ipynb`

## Цель

Собрать таблицу `client_id | snapshot_date | признаки | segment | product | target`, где признаки честно из прошлого, а таргет честно из будущего.

**Самая важная неделя курса.** Ошибка здесь обесценивает всё дальнейшее.

## Схема окон (менять нельзя — иначе результаты несравнимы)

Для `snapshot = '2025-01'`:

| Отрезок | Месяцы | Назначение |
|---|---|---|
| Окно наблюдения | 2024-08 … 2025-01 | признаки |
| Слепой зазор | 2025-02 … 2025-03 | не используется вообще |
| Окно прогноза | 2025-04 … 2025-06 | таргет |

Зазор нужен, чтобы прогноз имел практический смысл: отдел удержания не успевает отреагировать на клиента, который уходит в следующем месяце. Константы — в `src/features.py`.

## Шаги

1. Зафиксировать определение таргета (4 пункта) в журнале и в первой ячейке ноутбука. Рекомендованное определение — тетрадь 2.3.
2. `window_bounds(snapshot)` — границы через `pd.Period`.
3. `make_features(obs, obs_end)` — **минимальная версия, 4 признака**: `rev_mean`, `rev_last`, `rev_last_to_mean`, `n_months`. Расширять будете на неделе 3.
4. `make_target(fut, alive, rev_mean)` — нет строк в будущем **или** revenue упал ниже 20%.
5. `build_snapshot(...)` — шесть блоков, скелет с комментариями в тетради 6.3.
6. Собрать по семи снапшотам из `SNAPSHOTS`, сохранить `data/processed/dataset.parquet`.
7. Три обязательные проверки + таблица доли оттока по снапшотам.
8. Таблица самопроверки на утечку по каждому признаку.

## Чего ожидать

Доля оттока по снапшотам должна меняться **плавно**. Медленный дрейф в одну сторону — норма. Немонотонные скачки или разброс в разы — баг.

## Пять подсказок

1. Соберите **один** snapshot и посмотрите глазами — потом цикл по семи.
2. Клиенты, исчезнувшие из будущего, — это и есть отток. `reindex(alive)`, а не `inner join`.
3. Месяцы вычитаются только через `pd.Period`. И помните: назад на `OBSERVATION_MONTHS - 1`, а не на 6.
4. Не отфильтровали «мёртвые души» — доля оттока поедет.
5. Скачок доли оттока между снапшотами — всегда баг. Порядок поиска: границы окон → потеря клиентов при merge → фильтр `alive` → определение таргета.

## Минимум, если не успеваете

Шаги 1–6 на трёх снапшотах (`2024-07`, `2024-10`, `2025-01`) + первые две проверки. Без работающего `build_snapshot` неделя 3 не начнётся.
