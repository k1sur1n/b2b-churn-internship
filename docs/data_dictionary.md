# Словарь данных

Учебный синтетический датасет B2B-клиентов телеком-компании. Период: 30
месяцев, январь 2024 — июнь 2026.

## `data/raw/clients.xlsx` — справочник клиентов (лист "Клиенты")

Один клиент = одна строка.

| Столбец | Описание |
|---|---|
| `client_id` | Идентификатор клиента |
| `segment` | Сегмент: малый / средний / крупный бизнес |
| `product` | Основной продукт: интернет / мобильная связь / телефония / облачные сервисы |
| `region` | Регион |
| `название_клиента` | Название компании-клиента |
| `connection_date` | Дата подключения (месяц, `YYYY-MM`) |
| `дата_расторжения` | Дата расторжения договора, если клиент явно ушёл (пусто, если контракт формально активен) |
| `текущий_статус` | Статус клиента: "Активен" / "Расторгнут" |

## `data/raw/usage/` — помесячное потребление (30 CSV-файлов, по одному на месяц)

Датасет большой (~1 млн строк, 50 000+ клиентов), поэтому потребление
выгружено **по месяцам отдельными CSV-файлами** — `data/raw/usage/2024-01.csv`,
`data/raw/usage/2024-02.csv`, ..., `data/raw/usage/2026-06.csv` — так обычно
и выглядят реальные production-выгрузки биллинга. Один файл целиком в Excel
на таком объёме просто не поместился бы (и открывался бы очень медленно).

Схема одинаковая для всех файлов, одна строка = клиент в конкретном месяце:

| Столбец | Описание |
|---|---|
| `client_id` | Идентификатор клиента |
| `month` | Месяц (`YYYY-MM`), совпадает с именем файла |
| `revenue` | Начисления за месяц, руб. |
| `traffic_gb` | Объём трафика, ГБ |
| `n_tickets` | Число обращений в поддержку за месяц |
| `debt` | Задолженность на конец месяца, руб. |
| `n_sim` | Число активных SIM-карт/услуг |

Чтобы прочитать всё сразу:

```python
import glob
import pandas as pd

files = sorted(glob.glob("../data/raw/usage/*.csv"))
usage = pd.concat([pd.read_csv(f) for f in files], ignore_index=True)
usage.to_parquet("../data/processed/usage.parquet")  # дальше работайте только с parquet
```

## Важно

- На таком объёме читайте `usage/*.csv` **один раз**, сразу сохраняйте в
  `data/processed/usage.parquet` и дальше работайте только с parquet (см.
  раздел 6.1 основного гайда про производительность — здесь это уже не
  просто совет, а необходимость).
- Клиент может отсутствовать в файлах за какие-то месяцы (например,
  если он подключился позже начала периода, или его данные закончились).
- Не все явления в данных очевидны с первого взгляда — это отражает реальные
  промышленные данные, где не всё лежит на поверхности. Внимательно
  пройдите EDA-чек-лист из `docs/week1_eda.md`, прежде чем строить признаки.

## Бонус: скрытые бизнес-паттерны

Как и в реальных промышленных данных, здесь помимо основной задачи оттока
спрятано несколько неочевидных явлений, характерных для настоящих B2B-данных
телекома (не придуманные "фокусы ради фокусов", а вещи, которые встречаются

разовые операционные сбои и т.п.). Часть из них может исказить ваши признаки
